## PRD P0 — UUID / Typed Column Filter Fix [DONE]
- Root cause: filter clauses used $p::{cast} (e.g. $1::uuid), causing PostgreSQL to infer
  the parameter OID as uuid during the extended query describe phase. tokio-postgres then

  serializing parameter".
- Fix: changed all typed casts to $p::text::{cast} so PostgreSQL infers $p as text.
  String serialises cleanly; PostgreSQL handles text→target-type coercion server-side.
- Extracted shared build_pg_where_clause(filters, col_type_map) helper from query_table_pg
  and count_table_pg — both functions now call the helper, eliminating the duplication that
  could re-introduce the bug.

  sequential parameter numbering. All 16 tests pass (cargo test).
